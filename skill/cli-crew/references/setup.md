# Project setup (onboarding)

Read this only when setup is requested (see SKILL.md "Start from the user's goal").

1. Run `crew init` from the intended project root. If it reports existing instructions, use them as written.
2. If it creates `AGENTS.md`, main completes that new file in the project's documentation language, using the
   README, build manifests, CI workflows and test layout as evidence. Record the project's purpose, meaningful
   paths, and exact development or verification commands with their source and working directory when known.
   Do not infer commands, invent team policies, or copy private paths or credentials. In an empty project, keep the
   instructions minimal.
3. Distinguish the shared working procedure from project-specific facts. Identify the authoritative requirements,
   how a new session finds the latest relevant handoff, which ongoing edits it must preserve, and how verification
   is recorded.
4. If the user names prior projects as examples, consult only the authorized instructions. Carry over applicable
   practices; keep personal paths, client data, tool-specific roles, and custom locking or folder layouts out of
   unrelated projects. Use an existing language or record convention only when there is evidence for it.
5. If setup was the whole request, review the file and stop. Otherwise continue the original task.
